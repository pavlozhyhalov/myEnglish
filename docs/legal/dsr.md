# Запити людей щодо їхніх даних (GDPR ст. 12–22)

Строк відповіді — **1 місяць** від отримання (можна продовжити ще на 2 місяці для складних, повідомивши людину). Безкоштовно. Канал — «Написати розробнику» (людина вже авторизована — особу підтверджено) або сторінка підтримки (тоді відповідати лише на email акаунта).

| Право | Як людина робить сама | Що робить адміністратор, якщо прийшов запит |
|---|---|---|
| Доступ і копія (ст. 15) | «Акаунт» → «Завантажити мої дані» (JSON: пристрій + повідомлення й звернення з сервера) | попросити людину натиснути кнопку; якщо не може — вибірка за `user_id` з останньої копії: `scripts/backup-decrypt.js` → `scripts/backup-restore-sql.js --user <uuid>` (те саме коло таблиць), передати лише їй |
| Виправлення (ст. 16) | профіль, налаштування | виправити в БД за запитом |
| Видалення (ст. 17) | «Акаунт» → «Видалити акаунт» (одразу: файли в бакетах, потім `auth.users` — таблиці каскадом) | якщо людина не може увійти: перевірити, що запит з email акаунта → видалити через Supabase Dashboard → Authentication → користувач → Delete (файли — бакети `voice-clips/<uid>`, `chat-voice`, `feedback/<uid>`). Копії зітруться самі за ≤ 35 днів — сказати про це людині |
| Обмеження (ст. 18) | — | позначити акаунт (заблокувати вхід у Dashboard), дані не видаляти |
| Заперечення (ст. 21) | відкликати згоду на AI, вимкнути пошук і присутність, сповіщення | для законного інтересу (журнал помилок, облік AI) — оцінити, чи є переважні підстави; відповісти |
| Відкликання згоди (ст. 7(3)) | «Налаштування» → «Ще» → «Дані» → «Дозволити AI-вчителя» | — |
| Перенесення (ст. 20) | «Завантажити мої дані» (машиночитний JSON) | — |
| Автоматизовані рішення (ст. 22) | — | таких рішень немає; пояснити, як AI оцінює рівень |

Записувати кожен запит (дата, людина, що просили, що зроблено, коли відповіли) — приватно, не в репозиторії.
